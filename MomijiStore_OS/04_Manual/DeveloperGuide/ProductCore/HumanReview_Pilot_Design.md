## 1. 目的

A 区分は「件数を増やす」ためのものではなく、**人が短時間で安全に確認できる商品だけを集める**ためのもの。Pilot で次を実データで確かめる。

1. 名称類似度 0.35 は適切か(低すぎて別商品が混ざっていないか)
2. 原価倍率 1.8 / 0.56 は適切か(単品とセットの取り違えを取りこぼしていないか)
3. A 区分に危険な商品が混入していないか(False Safe)
4. 確認表の操作性
5. 1件あたりの確認時間
6. 判断に必要だった Evidence
7. Human Decision の選択肢が足りているか

**A 区分も1件ずつ Human Decision を記録する。Pilot 中も Pilot 後も、A 区分を自動承認・一括承認しない。**

## 2. 標本の選び方(40件)

閾値の妥当性を確かめるには、**閾値の近く**を多めに見る必要がある。A 区分 331件を次の層に分け、層ごとに無作為に抽出する(乱数の種を記録し、同じ標本を再現できるようにする)。

| 層 | 条件 | 件数 | 見たいこと |
|---|---|---|---|
| S1 名称境界 | 名称類似度 0.35〜0.50 | 12 | 0.35 が低すぎないか |
| S2 原価境界 | Pricetar との原価倍率 1.4〜1.8 / 0.56〜0.72 | 8 | 1.8 / 0.56 が緩すぎないか |
| S3 多出品 | 出品が3件以上 | 5 | 出品ごとの入数違い(まとめ売り)の混入 |
| S4 名称に数量・容量表記 | 商品名に「個」「本」「枚」「ml」「g」等の数字 | 5 | 単品とセットの取り違え |
| S5 対照 | 上のどれにも当たらない A(名称類似度 0.8 以上など) | 10 | 「本当に簡単な A」の確認時間の基準 |

- 層が重なる商品は、上の層から順に1回だけ数える。層の件数が足りなければ S5 から補う。
- 比較のため、**B 区分から5件・C 区分(6件)から全件**を「対照」として同じ手順で確認する(A と同じ確認時間で判断できるか、C の検出理由が妥当か)。これは Pilot の 40件とは別に数える。

## 3. 確認手順

1. review_batch を1つ作る(`review_type = LEGACY_MAPPING`。Pilot であることを `note` に記録)。
2. 確認表の見本(移行設計 §5)に Pilot 用の列を足して出力する:

| 列 | 入力者 | 内容 |
|---|---|---|
| human_decision | 人 | APPROVE / CORRECT / REJECT / HOLD / NEEDS_MORE_INFO |
| pilot_should_be_class | 人 | 本来の区分(A のままで良い / B が妥当 / C が妥当) |
| pilot_risk_found | 人 | 見つかった危険(なし / 単品とセットの取り違え / 別商品 / 入数違い / JAN 誤り / その他) |
| pilot_evidence_used | 人 | 判断に使った根拠(複数選択: 商品名 / JAN / 出品ページ / Pricetar / 原価 / 現物 / 仕入明細) |
| pilot_seconds | 人(またはタイマー) | その行の確認にかかった秒数 |
| pilot_comment | 人 | 選択肢が足りなかった場合の説明・操作で困った点 |

3. 確認者は1件ずつ判断する。**Pilot の判断は Product Core の正式承認として取り込まない**(Pilot は本番 DB 未適用の段階で行うため。取り込む場合は改めて承認を得る)。
4. 可能なら同じ標本を2人が独立に確認し、判断の一致率を見る(1人の場合は省略)。

## 4. 指標

| 指標 | 定義 | 目安(暫定) |
|---|---|---|
| **False Safe 率(最重要)** | A 区分のうち `pilot_should_be_class` が B / C、または `pilot_risk_found` が「なし」以外の割合 | **0件を目標**。1件でも出たら §5 の見直しを行う |
| 層別 False Safe | S1〜S5 ごとの False Safe の件数 | S1 / S2 に集中すれば閾値の見直し対象 |
| 確認時間 | A の1件あたりの中央値・90 パーセンタイル | A: 中央値 30 秒以内(B・C と比べて明確に短いこと) |
| 判断の分布 | APPROVE / CORRECT / REJECT / HOLD / NEEDS_MORE_INFO の件数 | A で HOLD / NEEDS_MORE_INFO が多ければ Evidence 不足 |
| 必要な Evidence | `pilot_evidence_used` の集計 | 出品ページ・現物が多ければ、確認表へ出す情報を増やす |
| 選択肢の不足 | `pilot_comment` で「選択肢が無い」とされた件数 | 0件 |
| False Alarm(参考) | C 区分のうち、確認の結果 A で良かったもの | 多すぎても安全上の問題はないが、確認負荷の目安 |

- False Safe は件数が少ないため、率より**1件ごとの原因**を重視する。

## 5. 結果の扱い(閾値の較正)

| 結果 | 対応 |
|---|---|
| False Safe 0件・時間も短い | 閾値を維持。A 区分の残り(291件)を同じ手順で確認(A も1件ずつ Human Decision を記録) |
| S1(名称境界)で False Safe | 名称類似度の閾値を上げる(例 0.35 → 0.5)案を作り、再分類した件数の変化と共に提示 |
| S2(原価境界)で False Safe | 原価倍率を狭める(例 1.8 / 0.56 → 1.5 / 0.67)案を作り提示 |
| S3 / S4 で False Safe | A の条件に「多出品」「名称の数量表記」の除外を追加する案を作り提示 |
| HOLD / NEEDS_MORE_INFO が多い | 確認表に出す Evidence(出品ページの URL・画像・入数)を追加 |

- 閾値の変更は**提案のみ**。変更後は A / B / C の件数と、変更で B / C へ移った商品の一覧を添えて承認を得る。
- 閾値を変えても「A = 簡易 Human Review 候補」であり、承認条件にはしない。
