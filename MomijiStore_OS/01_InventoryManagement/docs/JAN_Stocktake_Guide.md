# JANスキャン棚卸し — 設計と操作(Step 1 MVP)

作成 2026-09-25 / 状態: **MVP(実地テスト前)**。正本(商品マスター・在庫管理テーブル)への書き込みは未実装・未承認。

## 1. これは何か / 何をしないか

| する | しない |
|---|---|
| JAN をスキャン → 商品マスターで P番号を特定(読み取り専用) | 商品マスター・出品テーブルの変更 |
| 数量を1件ごとに記録(追記のみ・取消はイベント) | 在庫管理テーブルへの反映(Phase 4 で別途承認) |
| 記録から集計xlsxを作る(何度でも同じ結果) | Amazon・楽天・プライスターへの在庫反映 |

**実棚は物理的な単品P単位。** 帳簿在庫との比較・差異金額は Step 3 以降。

## 2. 起動

```bash
cd ~/MomijiStore/MomijiStore_OS/01_InventoryManagement/Python/Stocktake
python3 stocktake_app.py            # この Mac だけ: http://127.0.0.1:8765/
python3 stocktake_app.py --lan      # LAN 内の MacBook・iPad からも(トークン付きURLが表示される)
python3 stocktake_app.py --data-dir /tmp/stocktake_practice   # 練習用(本番の記録に混ぜない)
```

- 同じ保存先で2つ同時には起動できない(二重書き込み防止のロック)
- 既定の保存先(`SourceData/Stocktake/`)だけが **本番**。`--data-dir` で別の場所を指定するとすべて **練習用** になり、画面上部に黄色の「練習用」が出る
- 画面が覚えるロケーションは「環境 + 保存先ID + セッションID + 端末ID」ごと。新しいセッションは必ず「未指定」から始まる
- `--lan` のときは macOS のファイアウォール確認が出ることがある。トークン付きURLは作業者にだけ伝える

## 3. 操作(マウス不要)

```
スキャン → (商品名・P番号・原価が大きく表示) → 数量 → Enter → 次をスキャン
```

| 操作 | キー | 操作コード(印刷して読んでもよい) |
|---|---|---|
| 決定 | Enter(スキャナーが自動で送る) | — |
| この商品をやめる | Esc | `CMD-CANCEL` |
| 直前の登録を取消 | `/` または F2 → 空のまま Enter | `CMD-UNDO` |
| JANなし商品(仮ID) | `*` または F4 → メモ → 数量 | `CMD-TEMP` |
| ロケーション切替 | 棚コード(例 `A-01-02`)をスキャン | `CMD-LOCCLEAR` で未指定へ |

| 画面の色 | 意味 | 作業者がすること |
|---|---|---|
| 緑「一致」 | P番号が1つに決まった | 数量を入れる |
| 黄「未登録JAN」 | マスターに無い | **そのまま数量を入れる**(検索不要。後で未登録一覧で処理) |
| 青「JAN重複」 | 同じJANの単品が複数(例: 50本/100本/200本入り) | 番号を選ぶ。分からなければ 0 か空 Enter(後で確認) |
| 紫「単品セット共通JAN」 | 同じJANに単品とセットがある(21JAN) | **単品へ自動確定しない。** 番号で「単品候補」(バラで置かれている)か「セット候補」(梱包されたまま)を選ぶ。商品名と現物が合わない・迷うときは 0(後で確認) |
| 紫「セット品JAN」 | セットにだけ付いたJAN | 梱包済みのセット数を入れる(換算は後で) |

「単品候補」はマスター上の種別であって物理的な1個とは限らない(例: サラテクト 4901080023414 は単品候補が ×4個・×5個 のまとめ買い品)。
画面は入数を推測しない。

**セット候補を選んだ登録は、セットP×セット数のまま「セット換算待ち」として記録する。** 入数を推測して単品へ換算しない
(2026-09-25 必須修正①。修正前は共通JANを単品へ自動確定しており、2本セット8個が単品8個として黙って記録された)。
修正前の規則で記録された行も、再集計では実棚に入れず要確認へ回す。

まとめ買い品しかPが無いJAN(②)・同じ現物に複数P(③)は、棚卸しシステムでは解決しない。0(後で確認)で記録して作業を続ける。
商品マスター/P番号/セット構成の正本変更は、別途の設計・承認で行う。
| 赤 | 登録していない(読み取りミス・ケースコード・数量欄にコード等) | 読み直す |

入力ミスの検出: 数量の空欄(0 と区別)・数字以外・**数量欄にJAN**・上限超え(9,999)・大量(300以上は再入力で確認)・
同じ端末で直前と同じ商品・数量・場所(15秒以内は確認)・チェックディジット不一致・外箱(ケース)コード。値は `stocktake_config.json`。

## 5. 集計(`stocktake_aggregate.py`)

```bash
python3 stocktake_aggregate.py ST-20261001-01            # 画面の「途中集計」「セッション終了」でも同じ処理
```

- 取消された登録は数えない(明細には残る)
- **JAN は集計のたびに照合し直す** → 棚卸し後に商品マスターへ登録すれば、未登録JANは再集計だけで実棚に入る
- 同一P は内部管理ID単位で合算し、ロケーション内訳を出す(A棚30 + C棚20 = 50)
- 同じ場所・同じ数量の複数登録は「二重カウントの可能性」として要確認に出す(自動では消さない)
- 「集計情報」シートの **集計結果ハッシュ** は、同じ記録・同じマスターなら必ず一致する(再現性の確認用)

シート: 実棚集計 / 未登録JAN / 仮ID / セット換算待ち / 要確認 / 明細 / 集計情報
